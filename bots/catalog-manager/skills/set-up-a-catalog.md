# Set up a catalog

Use this when the user wants their own catalog and `catalog_repo` is empty.

1. Make sure GitHub is connected.
2. Ask how they want to be credited (their name, X handle, or GitHub username) and which link their name should go to. Ask which license their bots should use: GPL-3.0, MIT, Apache-2.0, or CC0-1.0. Explain that GPL-3.0 keeps changed copies open, MIT and Apache-2.0 let anyone reuse them with credit, and CC0-1.0 puts them in the public domain. The template's own scripts and docs stay GPL-3.0 either way. Ask for `private_denylist` if you don't have it yet.
3. Create a new public repository from the template https://github.com/{{template_repo}}. Name it `bot-catalog-for-grok-bot` unless the user wants another name. In the browser this is "Use this template", then "Create a new repository".
4. In the new repository, run the "Set up catalog" workflow on `master` with their credit, link, and license as inputs. Wait for it to finish green. It points the catalog at the new repository, and removes the template note and you from the README.
5. Protect the repository by adding the two rulesets in its `.github/rulesets/` folder, `protect-master.json` and `protect-release-tags.json`, exactly as written. In the browser, that is Settings, then Rules, then Rulesets, then "New ruleset", then "Import a ruleset", once for each file. Then turn on private vulnerability reporting, which in the browser is Settings, then Security, then "Private vulnerability reporting". Then turn on automatic deletion of merged branches, which in the browser is Settings, then General, then "Automatically delete head branches". Then make workflow runs from outside contributors wait for approval, which in the browser is Settings, then Actions, then General, then "Require approval for all external contributors".
6. Offer to add `private_denylist` as a repository secret named `PRIVATE_DENYLIST`, so CI also rejects any file that contains one of its entries. First look up who has write access to the repository, and tell the user that anyone with write access (name them, for example "currently only you" or "currently you and two others: alex and sam") can read the secret through a workflow on a branch of their own. Suggest leaving it out: you remove personal details from everything before it is pushed, and nothing is published until the user has seen every file and said yes. Add it only if they want it, one entry per line. In the browser, that is Settings, then Secrets and variables, then Actions.
7. Save the repository's owner/name as `catalog_repo`. Give the user its link, and offer to add their first bot.
