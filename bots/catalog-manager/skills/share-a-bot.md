# Share a bot

Use this when the user wants to share one of their bots, or ship a change to one that is already shared from `catalog_repo`. Sharing covers everything: adding the bot to the catalog, and the first time, publishing the public copy that people add. Merging releases it.

1. Ask which bot. If `catalog_repo` still has a `dev` branch, run the "Update a catalog from the template" skill first, because its checks fail pull requests into `master` until `dev` is gone. Read `CONTRIBUTING.md` in `catalog_repo` for the file format, and check whether `bots/` already has this bot.
2. Get the bot's full definition: its description, every skill and every routine, word for word, plus its avatar's shape and color. Read it directly if you can. Otherwise message the bot and ask it to send you exactly that, with nothing summarized. If neither works, give the user a short message to paste into that bot and ask them to paste its answer back to you.
3. Draft the files for `bots/<slug>/`: `bot.toml`, `instructions.md`, one file per skill in `skills/`, one file per routine in `routines/`, and `CHANGELOG.md`. Use a short lowercase slug. Use the shape and color of the bot's built-in default mark in Grok Bot. If it has a custom picture, pick the closest shape and color. Leave out the "Check for bot updates" skill and routine, because the catalog adds those.
4. Remove everything personal: everything in `private_denylist`, plus names, email addresses, accounts, handles, phone numbers, addresses, links to private files or tools, keys, and anything the bot knows only from its memory or its conversations. Where a skill needs one of those, rewrite it to ask the user and remember the answer.
5. If the bot is already in the catalog, bump `version`: patch for wording fixes, minor for new skills or routines, major for changes to what the bot does on its own. Add a changelog section for the new version that says what changes for the people using it.
6. Show the user every file in full, then a separate list of everything you removed. Then say what happens next: you will open a pull request, for a new bot create its public copy and share link, and merge it, which releases it. Wait for their yes. That yes covers every step below for this bot only.
7. Create a branch off `master`, commit the approved files exactly as approved, and open a pull request into `master`. Change only this bot's folder. Wait for the Build workflow to add the generated files and for the check to finish.
8. If the bot is new, the check fails until the bot has a share link. Publish it from the pull request:
   1. Create a new Bot. Have it fetch https://raw.githubusercontent.com/<catalog_repo>/<branch>/dist/<slug>.md and set itself up exactly as that file's "How to apply" section says. Give it the name in `bot.toml`, and have it set its avatar with Grok Bot's built-in default mark using the shape and color listed there. It must not generate or upload a custom picture; if one is installed, it clears it. This copy is the one people will add, because it carries the update check.
   2. Create a public share link for the new Bot: Share, then "Create template", then "Public link". Set the template's description to the `summary` in `bot.toml`, word for word. That description is what people see on the share link, so never put the bot's instructions there. If you can't, ask the user to do it and paste you the link.
   3. Set `share_url` in `bots/<slug>/bot.toml` on the same branch to the link, and change nothing else.
   4. If the bot's files change after this, have the published copy apply the new `dist/<slug>.md` from the branch the same way, then choose Share, then "Update template", before you merge. Keep the template's description set to the `summary` in `bot.toml`.
9. When the check passes, merge the pull request. If it fails for any other reason, show the user the error and what you would change, and wait.
10. Confirm that the Release workflow created the tag `<slug>-v<version>`. Tell the user it's live. For a new bot, give them the share link and point out its **Add Grok Bot** button in the README. For an update, say that people who added the bot will be offered it within a day.
